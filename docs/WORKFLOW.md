# 这个 workflow 为什么长这样

一份设计记录，写给三个月后的你（那时你已经忘了为什么是 1+3，而不是 5 篇）。

## 1. 问题不是"信息不够"，是"注意力没有预算"

旧版每次检索 14 本期刊、每本 6 篇，再去重、逐篇调用模型。单看每一步都合理，合起来的结果是：一个下午读完 40 条摘要，记住 0 条。

信息过载的解法不是更快的摘要，而是**先设上限，再排序**：

- 每天 1 篇精读 + 3 篇速览，写死在 `quota` 里；
- 上限决定了下游所有设计：既然只能留 4 篇，就必须有真正的淘汰，而不是"全都给你，自己挑"。

## 2. 三层过滤，每层职责不同

```
召回   PubMed（36 本期刊 + 1 条跨刊主题检索）
        → 150–250 篇
粗排   确定性规则，无模型
        → 36 篇
精排   agnes-2.5-flash 批评分（12 篇/批）
        → 4 篇
```

**为什么粗排必须存在**，即使有模型：

1. **可解释**：你能看到"因为期刊 A 级 + RCT + n=1208"而进候选；
2. **可离线**：Key 没配、额度用完、API 抽风，页面仍然有东西读；
3. **省上下文**：把 200 篇摘要全塞给模型，既贵又会让它"平均地打分"——这是排序任务最常见的失败模式。

粗排的分数不进最终分（只占 22%），它的职责是**保证不遗漏**，不是做最终判断。

## 3. 为什么是 1 + 3，而不是 5 篇精读

- 精读卡的信息密度大约是速览的 8–10 倍：一个问题、一个设计、两三条证据、三个追问。2 篇精读就会挤掉速览，5 篇则当天就读不完，第二天开始欠债。
- 速览的作用不是"知道"，是**保持视野**：三篇来自不同期刊、不同主题，防止你连续一周只看种植。
- 多样性是硬约束，不是喜好：选择时同一期刊、同一主题簇最多出现一次，池子不够才放宽。

## 4. 为什么用 PubMed，而不是 Europe PMC

最初用 Europe PMC 的 `FIRST_PDATE` 做时间窗，结果 3 天窗口内 *Journal of Dental Research* 命中 0 篇——因为 EPMC 的 `FIRST_PDATE` 跟着纸本刊期走（10 月 1 日），而 PubMed 的 `Date - Publication` 跟电子上线走。

对"每日"产品，**时效性优先于字段丰富度**。于是：

- 检索与摘要：PubMed E-utilities（esearch + efetch XML）；
- 不依赖第三方 citation count（多数新论文本来就是 0，噪音大于信号）。

代价是拿不到被引数，可以接受：判断"影响"是模型和你的工作，不是引用数。

## 5. 学科思维拆成三个可操作的动作

"培养学科思维"很容易变成一句空话。这里把它拆成卡片上具体的三件事：

| 动作 | 落在哪里 |
|---|---|
| 学会提问 | 精读卡第一栏「主诉 / 问题」：它真正想回答什么，而不是"评估了 X" |
| 认识证据层级 | 左侧「证据探针」+ 「检查 / 设计」：体外、动物、队列、RCT、Meta 的位置决定结论能推多远 |
| 看见争议 | 周报的 `tension`：两种证据互相矛盾时，分歧点在哪（人群？终点？随访？） |

再加一条「可迁移」：这篇的方法能不能搬到你的课题。读文献的复利来自方法迁移，不是结论收藏。

## 6. 反馈闭环为什么这么"土"

没有后端，也不该为了点赞功能引入一个后端。所以：

```
页面点击  →  localStorage  →  导出 JSON  →  feedback/inbox/  →  下次运行写入 state/blocked.json
```

- 「不感兴趣」是**永久屏蔽**（进 `blocked.json`），因为重复推荐同一篇是最伤信任的失败；
- 「已读 / 收藏」只影响本机进度条，不上传——阅读进度是隐私；
- 每周导出一次就够了，不需要天天维护。

代价是反馈有延迟（下次运行才生效）。换来的是：零服务器、零账号、零数据库。

## 7. 刻意没做的事

- **不做全文精读**：全文要过版权与解析，收益不稳定；摘要 + 结构化追问已经能支撑 80% 的判断。
- **不做"每日 20 篇"**：那只是把过载从检索搬到页面。
- **不做自动写综述**：周报只给地图和空白，写还是你自己写——这是"学科思维"和"文献搬运"的分界线。
- **不做多用户**：所有设计围绕一个研究者的注意力预算；多用户会让排序目标变成"平均满意度"，正好是你不需要的东西。

## 8. 什么时候该改这个设计

- 连续两周「精读」都被你判定为不相关 → 改 `research_questions`，不是改权重；
- 「待回看」长期超过 10 篇 → 配额太高，降到 1+2；
- 周报的 `gaps` 连续三周重复 → 说明你的问题已经收敛，该动手做实验而不是继续读。

## 9. 邮件为什么也做「四篇」，而不是「每日摘要」

邮件是最容易失控的渠道：一旦变成"今天有 37 篇更新"，它就会被自动归档，和没有一样。

所以邮件复用同一份 JSON，不做二次筛选，也不加"更多推荐"：

- **同源**：邮件与网页读同一个 `data/daily/*.json`，不存在两套排序；
- **双版本**：HTML 负责结构（四段式、证据、按钮），纯文本负责在弱网/纯文本客户端里仍然可读；
- **失败不影响数据**：先落盘、提交，再发信；发信异常只记日志，避免因为邮箱问题丢掉当天的 digest；
- **可关**：`delivery.email.enabled: false` 一行就能停，不需要改代码。
